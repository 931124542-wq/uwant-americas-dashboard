# Buen Fin活动订单接入 · 11.17.1

经营看板可通过同一“导入经营报表”入口读取活动HTML，继续支持原Excel及JSON备份。只提取明确声明的JSON订单、SKU、期间、金额换算、覆盖和截止时间，不加载或执行导入HTML中的脚本、字体及链接。真实源报表和订单数据不进入公开仓库。

## 业务口径

- 活动报表显示非取消订单台数和源报表未税订单金额，保留待付款、待接受、待发货、已发货、已送达等原状态。订单不自动等于已付款、实销或已结算收入。
- 取消订单独立列示，不先纳入再重复扣除。CSV同时列源数量/金额及计入非取消统计的数量/金额，明确取消标记，合计可对应页面。
- 源报表金额按其明确写出的除数换算，汇总使用未逐行舍入的值；不按当前报价重算，也不认证该金额为实收。美元汇率只保留来源参考，不自动混合币种。
- 每个渠道保留实际来源截止时间。已覆盖某日不代表该日全天或结算已完整；没有覆盖的渠道日期不补零，已覆盖且无订单的型号可显示0。
- 日期按源页眉明确年份和交易日归属，不依赖源星期文本，原文件不改写。
- 原SKU和UPC保留；与历史库存档案同UPC但名称不同的型号仅提示关联，不改写历史SKU。

## 原数据与更新

活动库与历史实销/库存库使用独立本机存储。活动不追加到旧实销，不扣减旧库存，不把采购当出货。经营页可切换活动、历史报表和原经营页面；库存页继续显示原日期并明确没有活动新库存快照。

同平台订单ID与源SKU组成订单行标识，相同重复行只保留一条，状态/金额冲突拒绝接入。同一文件重复读取不追加；不同文件版本保留并单独选择，不把多个快照相加。无效导入保留已有数据，备份明确针对当前版本。当前浏览器保存，文件不上传。

## 验证及发布边界

使用合成数据检查取消、待付款、覆盖与零值、订单冲突、版本保留、金额及CSV分母。浏览器检查HTML不执行、旧历史/库存不变、日期/渠道/SKU筛选、刷新、重复导入、备份、版本选择、手机端及无上传请求。

真实文件核对及已载入数据的本机版均在公开仓库外完成。CI只使用合成HTML；代码发布不代表用户当前浏览器已导入该内部报表。已有市场源数据和历史隔离规则保持不变。
